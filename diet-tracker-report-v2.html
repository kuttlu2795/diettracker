1Executive summary

Diet Tracker already covers the core loop every major competitor is built around — log food, track calories/macros, see trends, hit a goal — and goes further than most free apps in two ways: it computes a full personalized nutrition plan (not just a calorie number) from goal-and-rate inputs, and it uses a three-layer food lookup (verified database → AI estimate → manual entry) so no food is ever a dead end. The gaps that remain against the big names are mostly ecosystem features — wearable sync, social/community, recipe saving, gamification — rather than core tracking accuracy. Section 5 lays these out as a prioritized roadmap.

Note on the comparison below: live web search wasn't available while preparing this report, so the competitor feature list is based on these apps' well-established, stable public feature sets rather than a fresh browse. The big-picture positioning is reliable; worth double-checking any single cell before quoting it externally, as apps do add features over time.

3What's implemented today

The full current feature set, grouped by area.

🏠

Dashboard

Animated rings for calories, steps, water, protein; energy-balance cards (BMR/TDEE-based); quick water add.

🔍

Food logging

Free-text search → Open Food Facts + Edamam → AI (Gemini) fallback → manual entry. Barcode & OCR label scanning. Editable macros. Recent-foods quick add.

🥚

Smart customizers

Egg (count/yolk/salt/pepper) and juice (type/sugar/size) quick-builders that turn choices into a precise lookup query.

📊

History

Today/Yesterday/Week/Month/Year views with animated bar chart and full entry list.

🧭

Plan

BMI, goal-rate-driven calorie/water/protein/carb/fat/fiber targets, meal-split table, live AI-generated veg & non-veg meal suggestions.

💧

Water reminders

Personalized daily ml target, evenly-spaced push notifications between wake/sleep, survives reboot.

👤

Profile

Height/weight/age/gender/activity level, Lose-Maintain-Gain goal with kg/week rate, all daily targets editable.

🔐

All personal data stored on-device (Room/SQLite); nutrition/meal APIs are free-tier, keys never hardcoded.

4What was added this round

Directly addressing "make Add Food more useful — accept anything the user actually eats."

AI nutrition fallback via Google Gemini Implemented

When Open Food Facts and Edamam both miss, the app now sends the exact description to Gemini's free tier and gets back a structured nutrition estimate — clearly badged "AI Estimated" with a review prompt, and every field stays editable. No API cost, no card required to start.

Guided customizers for eggs & juice Implemented

Typing "egg" or "juice" now offers a quick picker (egg count, yolk in/out, salt, pepper / juice type, added sugar, serving size) instead of guessing — the choices build a precise description that's what actually gets looked up, so nothing is hardcoded. The same pattern can be extended to coffee, rice, roti, etc.

Manual entry fallback Implemented

If even the AI estimate isn't wanted or available, the user can enter values themselves — logging is never blocked.

Editable macros on every result Implemented

Calories/protein/carbs/sugar/fat/fiber/sodium are now real input fields in the food editor for every source (database, AI, manual, OCR) — not just read-only text.

Source badges Implemented

Every result is labeled Database / AI Estimated / Manual so the user always knows how trustworthy a number is at a glance.

Recent foods quick-add Implemented

New — when the search is empty, the app shows recently logged foods so a repeated meal (same breakfast most days, for example) is a single tap instead of a full search.

5Recommended roadmap

Gaps identified from the comparison table, prioritized by user value vs. effort. The original roadmap remains useful for future work; the Health Connect and My Meals items are now implemented in v2.

Recipe builder / "my meals" Implemented v2

Implemented locally. Users combine recent foods into a named My Meal and save the summed nutrition in Room for reuse.

Health Connect sync Implemented v2

Implemented as the Android health-data hub: the app requests granular permissions and imports steps, weight, heart rate and sleep-session data.

AI meal-photo recognition High value

Natural next step beyond label-OCR: point the camera at a plate of food and let Gemini's vision capability estimate what's on it and roughly how much — this is where AI-native apps are heading and would leapfrog most incumbents.

Streaks & light gamification Medium value

A simple "logged N days in a row" streak and small milestone badges meaningfully improve retention in every competitor that has them (HealthifyMe, Lose It!) — cheap to build on the existing food-log data.

Data export (CSV/PDF) Medium value

Let users export their log for their own records or to share with a doctor/dietitian — straightforward given everything's already in Room.

Micronutrients (vitamins & minerals) Medium value

Edamam's nutrition-analysis response already includes vitamin/mineral data that the app currently ignores — surfacing it is mostly a UI addition, not new API integration.

Extend guided customizers Medium value

Apply the egg/juice pattern to a handful of other high-variance foods: coffee/tea (sugar, milk type), rice (white/brown, cups), roti (count, ghee or not) — same "build a precise description" approach, no new architecture needed.

Home-screen widget Nice to have

A small widget showing today's calories/water at a glance, with a tap-to-add-water action, reduces friction to open the app.

Social / friends / shared challenges Nice to have

Highest build cost of anything on this list (needs a backend), and the app's current on-device-storage, no-account design is itself a privacy advantage worth preserving — worth deliberately deciding against this rather than defaulting into it.

6APIs & free-tier reference

Everything the app calls, and what "free" means for each — useful for setting expectations as usage grows.

Free, no key

Open Food Facts

Unlimited, keyless. Packaged/branded product search + barcode lookup. Community-maintained database.

Free tier

Edamam Nutrition Analysis

Free tier has a daily call limit (check current terms at signup) — natural-language parsing for generic/home foods.

Free tier

Spoonacular

150 points/day free; a meal-plan generation call costs a few points each — fine for a few plan refreshes per user per day.

Free tier

Google Gemini (1.5 Flash)

Genuinely free tier with rate limits (requests/minute and /day) — no credit card required to start. Used only as a fallback, so call volume stays low.

Free, on-device

ML Kit (Barcode + OCR)

Google's on-device models — no network call, no per-use cost, works offline.

Cost outlook: at realistic personal/small-scale usage, all five stay within free tiers indefinitely. If this ever moves toward many concurrent users, Edamam/Spoonacular free-tier daily caps would be the first thing to hit — worth monitoring via each provider's dashboard.
